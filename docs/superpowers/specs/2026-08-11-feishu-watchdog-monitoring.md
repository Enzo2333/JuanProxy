# 飞书 Watchdog 监控设计

## 目标

为 JuanProxy 增加独立于 Electron 主进程的飞书告警，通知活动路由实际倍率切换、指定账号余额不足、长时间没有可用站点、程序异常、Codex 普通对话回答完成和目标完成/暂停。六类通知可分别开关；持续异常每 30 分钟提醒一次，恢复时通知一次。

## 非目标

- 不接收飞书命令，不实现交互式应用机器人。
- 不替代现有站点自动恢复、故障切换或账号同步。
- 不在消息中发送 API Key、密码、会话、Cookie 或完整 Webhook。
- 不统一换算不同站点的币种；阈值沿用远端展示余额的数值单位。

## 方案选择

采用独立 Node.js Watchdog，由 Windows 任务计划在用户登录时启动并在异常退出后重启。Watchdog 使用 Node 22 原生 `fetch` 和文件 API，不增加运行时依赖。

Watchdog 每 30 秒读取 `%APPDATA%\JuanProxy\config.json` 并访问配置端口的 `/__proxy/health`。配置文件已使用临时文件加原子替换保存，外部只读不会介入 JuanProxy 的写入流程。站点可用性复用现有 `switching-policy.js` 判断，避免形成第二套规则。

未采用的方案：

- 主进程直接推送：主程序退出后失去通知能力。
- 新增心跳文件：需要主程序持续写盘，而现有健康接口和原子配置已经覆盖所需状态。
- 仅跟踪日志：日志格式不是状态接口，容易重复或漏报恢复。

## 配置模型

在现有配置中新增全局 `monitoring`：

```json
{
  "monitoring": {
    "enabled": false,
    "feishuWebhook": "",
    "checkIntervalSeconds": 30,
    "failureThreshold": 3,
    "repeatIntervalMinutes": 30,
    "noUsableSiteDelayMinutes": 5,
    "notifications": {
      "multiplierChanged": true,
      "lowBalance": true,
      "noUsableSite": true,
      "programIssues": true,
      "answerCompleted": false,
      "goalStatusChanged": false
    },
    "rules": [
      {
        "accountId": "ACCOUNT_ID",
        "enabled": true,
        "balanceThreshold": 10
      }
    ]
  }
}
```

规则以 `accountId` 为唯一键，仅控制该账号的余额提醒。同一远端账号关联的全部站点共用一套开关和阈值；在任一关联站点修改都会更新同一规则。账号不再关联任何站点时清理其规则，旧版 `siteId + accountId` 规则在加载时按账号合并。

Webhook 是本地敏感配置：界面只显示“已配置”，输入框使用密码样式；运行日志和飞书消息不输出该值。

## 告警状态

Watchdog 维护独立的 `%APPDATA%\JuanProxy\feishu-watchdog-state.json`，按告警键记录当前状态和上次发送时间，并按会话事件键保存 Codex 通知的待发送项、目标状态和去重记录。进程重启后继续去重。

| 告警键 | 触发条件 | 恢复条件 |
| --- | --- | --- |
| `proxy-unreachable` | 健康检查连续失败 3 次 | 健康检查成功 |
| `no-usable-site` | 当前不存在可用且未处于限流暂停的站点，默认持续 5 分钟 | 至少一个站点恢复可用 |
| `low-balance:<accountId>` | 最近一次账号同步成功，且余额数值小于等于独立阈值 | 余额回到阈值以上或规则关闭 |

倍率状态单独保存当前活动路由的站点和实际倍率。首次运行只建立基线；站点变化但实际倍率相同不通知，同站点同步后实际倍率变化也通知。发送失败时不更新基线，下一轮继续尝试。

余额和程序异常首次进入时通知，无可用站点达到延迟后通知；异常未解除时每 30 分钟提醒，恢复时通知一次。关闭某类通知会静默清理对应活动状态，不额外发送恢复消息。

健康检查失败时，Watchdog 可以读取最新运行日志，为告警附带最近的 `app.bootstrap`、`process.uncaughtException` 或 `proxy.start-error` 摘要；其他日志不触发额外消息。

## 飞书消息

使用飞书群自定义机器人 Webhook 发送交互卡片：

- 标题：直接显示具体事件；持续或恢复状态附在事件标题末尾。
- 内容：异常类型、站点名、脱敏账号名、当前余额/阈值、发生时间和持续时间。
- 颜色：异常红色、持续提醒橙色、恢复绿色。

请求设置短超时。飞书发送失败只输出 Watchdog 错误并在下一轮重试，不影响 JuanProxy。账号仅展示脱敏后的用户名；消息不包含请求正文和凭据。

## 界面

- “路由策略”增加“飞书监控”：全局开关、六类通知开关、无可用站点持续分钟数、Webhook、测试消息、安装启动及停止移除后台任务。
- “站点策略”增加当前账号的余额提醒开关与余额阈值，同账号关联站点共用配置。
- 没有远端同步账号时禁用余额阈值。

## Windows 运行

提供安装和移除脚本管理当前用户的任务计划：

- 用户登录时启动 Watchdog。
- 已在运行时不启动第二个实例。
- 异常退出后由任务计划重启。
- Watchdog 关闭全局监控时保持低成本轮询配置，使再次启用无需重装任务。

## 验收标准

1. 主程序停止后，连续三次健康检查失败产生一次飞书告警；恢复后产生一次恢复通知。
2. 全部站点不可用持续配置时间后告警，任一站点恢复后通知。
3. 每个 `accountId` 可以设置不同余额阈值，也可以独立关闭提醒；同账号关联站点共用配置。
4. 余额仅在成功同步的数据上比较；同步异常不会被误报为欠费。
5. 同一异常在 30 分钟内不重复，持续超过 30 分钟后提醒，恢复只通知一次。
6. Watchdog 重启后仍能保持告警去重状态。
7. 飞书消息、运行日志和界面状态不暴露 API Key、密码、Cookie、会话或完整 Webhook。
8. 现有代理、站点切换、同步及自动恢复测试保持通过。
9. 活动路由实际倍率变化时通知；首次建立基线和同倍率换站不通知。
10. 六类通知可分别关闭，关闭后不发送该类恢复消息。
11. Codex 普通回答完成只按根会话成功的 `task_complete` 通知；首次启用不补发历史 turn，发送失败可重试且不发送回答正文。
12. 目标处于活动、暂停或阻塞状态时不发送单轮回答通知；目标暂停或完成分别通知，目标完成后的普通对话恢复回答完成通知。
